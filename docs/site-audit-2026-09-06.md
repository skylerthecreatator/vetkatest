# Проверка и исправление сайта ВЕТКА — 6 сентября 2026

## Что исправлено

- Цена, заголовок, ссылка и фото композиции дня публикуются одним комплектом, только после успешной загрузки и декодирования фото.
- VPS получает обновление в фоне раз в две минуты через прежний Vercel-мост. Посетитель получает готовую локальную фотографию WebP, не ожидая Telegram.
- Снимок хранится в `/var/lib/vetka/bouquet-day`, переживает перезапуск; фото имеют неизменяемые адреса по хешу содержимого.
- Обрыв сети, повреждённое изображение и запоздалый старый пост не подменяют текущую пару фото/цена. При длительной потере синхронизации (24 часа с последней успешной проверки) сервер перестаёт выдавать предложение.
- Публичные временные Telegram-ссылки больше не перезаписывают стабильный file_id из webhook. Повторная проверка того же поста получает свежую ссылку.
- Заданы ограничения времени ожидания и размера фото. Для сохранённого изображения проверяется целостность при перезапуске.
- При возвращении в давно открытую вкладку клиент перепроверяет композицию; скрытые вкладки не опрашивают сервер.
- Три декоративных изображения переведены в WebP: 3 385 134 → 332 872 байта (около −90%). Компоновка не менялась.
- Прошедшая дата ближайшего потока школы заменена на «Даты ближайшего потока — по запросу».
- Для сайта установлена отдельная Node.js 22.23.2; системная Node.js не заменена. Аудит production-зависимостей: 0 известных уязвимостей на момент проверки.

## Инфраструктура и откат

- Только точный маршрут `/api/bouquet-day` переключён на VPS. Остальные `/api/` (заявки, бот) сохраняют прежний Vercel-маршрут.
- Фоновая синхронизация всё ещё зависит от Vercel и доступности Telegram с его стороны. Это не полный перенос бота на VPS.
- Резервная копия файлов до изменения: `/var/backups/vetka-before-bouquet-20260906.tar.gz`.
- Исходная конфигурация Nginx сохранена в `/etc/nginx/vetka.before-local-bouquet-*`; переключатель проверяет `nginx -t` и откатывает конфигурацию при ошибке.
- Настройка службы: `/etc/systemd/system/vetka.service.d/bouquet.conf`. Диагностика: `/healthz` (готовность снимка, время последней успешной проверки, обезличенный код ошибки).
